# 2. 第一批：把现有 Android 功能完整跑通并修好

不要停在“构建成功”。

## 2.1 真实牌桌照片

在 Lenovo TB710FU 或当前 Android 设备上直接走完整流程：

```
选择牌桌照片
→ YOLO 检测
→ 直接点击图片中的检测框分配手牌/牌河/忽略
→ 必要时修改识别牌面
→ 补录漏检牌
→ 形成 13 或 14 张本人暗手
→ 导入
→ 自动显示分析
→ 查看进张/出牌建议
→ 撤销
```

实际检查：

- 图片框是否容易点击。
- 选中后的颜色是否容易分辨。
- “试选底部13张 / 14张”是否真正节省操作。
- 快捷选错后能否直接修。
- 未分配检测框是否不会阻止导入。
- 忽略框是否不会进入局面。
- 补漏牌是否方便。
- 13 张能否正常显示进张。
- 14 张能否正常显示出牌建议。
- 同种牌超过 4 张时是否正常拒绝。
- 导入错误是否直接显示原因。
- 导入成功是否自动分析。
- 撤销是否恢复导入前状态。
- 撤销后旧分析是否消失。

出现问题直接修，不额外建立自动化 UI 测试平台。

## 2.2 游戏截图连续导入

国标、四川各自实际测试：

### 13 → 14

- 当前手牌 13 张。
- 导入下一张 14 张截图。
- 应视为当前摸牌后的 14 张。
- 自动刷新分析。

### 14 → 13

- 当前 14 张。
- 导入下一张 13 张。
- 只有用户明确选择“减少的牌是我打出的”时才加入已见牌河。
- 没有确认就只更新当前手牌，不推断历史。

### 13 → 13 但牌面不同

- 允许继续本局。
- 不要求构造完整摸打历史。
- 当前手牌正确优先于事件还原。

### 四川

必须保持：

- 定缺。
- 四川牌墙逻辑。
- 四川分析。
- 换牌后不残留旧和牌事件。

### 修改牌面

用户一旦修改任一识别槽：

- 旧“确认这张是弃牌”的状态必须清除。

## 2.3 现有功能实测遇到 Bug

优先级：

1. 无法完成导入。

# 3. 第二批：直接实现 Android 游戏内悬浮助手 MVP

这部分是当前项目主线，不能再只写计划。

目标：

```
打开 Mahjong Copilot
→ 启动游戏助手
→ Android 请求悬浮窗权限
→ Android 请求 MediaProjection 屏幕共享
→ 切到麻将游戏
→ 出现小悬浮球
→ 点击悬浮球
→ 截取当前游戏画面一帧
→ 识别当前手牌
→ 调用现有规则和出牌建议
→ 悬浮窗显示结果
```

第一版不需要自动刷新。

## 3.1 Android 原生结构

保持简单。

可以新增：

- `GameOverlayPlugin`
- `GameOverlayService`

不要建立额外 service framework。

原生端只负责：

- 检查 / 请求悬浮窗权限。
- 请求 MediaProjection。
- 启动和停止前台 Service。
- 创建悬浮球。
- 悬浮球拖动。
- 点击悬浮球截取当前屏幕一帧。
- 将截图传给 Capacitor / WebView。
- 接收 JS 返回的简短建议文字。
- 更新悬浮窗文字。
- 点击建议区域可回到 Mahjong Copilot。
- 停止时清理悬浮窗和 MediaProjection。

接口尽量少，例如：

```ts
GameOverlay.start()
GameOverlay.stop()
GameOverlay.setText(...)
GameOverlay.addListener('frameCaptured', ...)
```

如果 Android 权限需要单独暴露，再加最少的：

```ts
GameOverlay.canDrawOverlays()
GameOverlay.requestOverlayPermission()
```

不要预先增加大量未来 API。

## 3.2 Android 权限和生命周期

按系统真实要求实现：

- 悬浮窗权限。
- MediaProjection 用户主动授权。
- Android 14+ 所需 mediaProjection 前台服务类型。
- 常驻通知。
- 停止服务时释放 VirtualDisplay / ImageReader / MediaProjection。
- MediaProjection 被系统终止时清理 overlay。
- 屏幕旋转后能够重新取得合理尺寸。
- 不绕过 `FLAG_SECURE`。
- 不自动控制游戏。

这些是系统必要条件，不属于“过度门控”。

# 6. 悬浮窗展示：从“提示器”升级为轻量 Copilot

这部分和悬浮窗 MVP **一起实现**，不要等以后重做 UI。

现有 `AnalysisResult` 已经提供：

- `shanten`
- `bestDiscard.tile / reason / ukeire / ukeireTiles`
- `improvingDraws`
- `waitingTiles`
- `suggestions`
- `patternDetails`
- `scoreEstimate / scoreNote`
- `warnings`

所以第一版直接增加一个很小的 **overlay formatter / view model**，把现有结果整理成悬浮窗内容即可。不要创建新的 AI Agent 或第二套决策引擎。

## 6.1 折叠态：始终显示的即时信息

### 14张，需要弃牌

示例：

```
建议：打 9万
1向听 · 5种12张进张
路线：混一色潜力
```

如果当前最重要的是速度：

```
建议：打 9万
1向听 · 5种12张
路线：牌效率优先
```

### 13张

```
1向听
进张：3万 / 6万 / 9筒
方向：三色同顺潜力
```

13张绝不能显示“建议打哪张”。

### 已听牌

```
结构听牌
待牌：3万 / 6万
国标：8番资格待核
```

### 已成牌

国标只有已确认满足条件时：

```
可以和牌
参考番型：混一色 + 碰碰和
```

如果结构成牌但8番/事件事实不足：

```
结构成牌
起和条件待确认
```

不要错误显示“可以和”。

## 6.2 牌型 / 番型展示规则

这是本轮新增重点。

悬浮窗要告诉用户“现在是什么结构、正在往什么方向发展”，但必须区分：

- **已确认构成**：只用于当前已经真实成立的番型/结构。
- **潜力 / 方向**：`suggestions` 对尚未完成的番型只能显示“混一色潜力”“三色同顺方向”等。
- **结构听牌**：只代表牌形听牌，不等同于国标已经满足8番。
- 四川继续使用四川自己的番/倍率描述，不套国标术语。

优先展示前 1–2 个最重要的 `suggestions`，不要把所有候选番型塞进悬浮窗。

例如：

```
当前结构：1向听
番型方向：混一色
兼容：碰碰和
```

或：

```
当前：结构听牌
潜力：全带幺
缺：1筒 / 9筒
```

## 6.3 展开态：点击悬浮建议后显示

展开卡片仍保持轻量，直接复用主 App 现有分析内容：

```
推荐：打 9万

原因：
减少孤张，保留更多有效进张

效率：
5种 / 12张

牌型：
混一色潜力
碰碰和潜力

关键进张：
3万 6万 2筒

警告：
国标8番资格仍需核对
```

可显示：

- 推荐弃牌理由。
- 向听。
- 有效进张种类/未见张数。
- 结构待牌。
- 最多 1–2 个番型方向。
- 主要缺牌。
- 国标8番/四川定缺等重要 warning。

不要在这里重复主 App 的完整分析页。

## 6.4 三路线展示：保留概念，但先用已有数据实现

用户提出的三种路线：

```
最高番
最高胡率
最佳平衡
```

可以作为产品方向保留，但**当前不要假装已有三个独立决策器**。

第一步先根据现有可解释信息形成简单路线标签：

- **牌效率优先**：向听 / ukeire 明显占优。
- **番型潜力优先**：某个高价值 `suggestion` 明显且缺牌较少。
- **平衡**：现有默认 `calculateBestDiscard` 推荐。

等以后真的有独立策略模型、模拟器或可靠风险估计，再把三路线升级为真正可切换策略。

禁止现在显示：

- “胜率 +2.4%”
- “72% 胡率”
- “EV +4200”
- “预计4巡听牌”

除非这些数字有实际计算来源。

## 6.5 展示层和决策层不要拆成大型新架构

可以新增一个很小的纯函数，例如：

```ts
formatOverlayAnalysis(result, lang)
```

返回：

```ts
{
  headline,
  summary,
  patternLine,
  detailLines,
  warning
}
```

它只负责**把已有 `AnalysisResult` 变成悬浮文字**。

不要因此新增：

- State Agent
- Strategy Agent
- Risk Agent
- Coach Agent
- Foundation Model
- Monte Carlo 服务
- Universal Mahjong State 新框架

当前项目已经有统一 `GameState` 和 `AnalysisResult`，先用好现有结构。

## 6.6 与用户提供的外部 MahjongCopilot 审视的取舍

用户提供的分析中，以下思想纳入本项目：

- “不只告诉打什么，还解释为什么”。
- 增加牌型/番型理解。
- 显示策略路线与权衡。
- UI 分即时信息、路径、解释三个层级。
- 后续可加入复盘和策略对照。

以下内容**不直接照搬**，因为它描述的是另一个以 Mortal / MJAI / MITM 为基础的日麻项目，也会造成当前项目膨胀：

- Mortal 直接决策层。
- MITM / Proxy 游戏捕获架构。
- 多 Agent。
- 新建 Universal Mahjong State 大重构。
- Monte Carlo 作为 P1 前置。
- 10000局 Benchmark 平台。
- Mahjong Foundation Model。

我们的当前主线仍然是：

```
Android MediaProjection
→ 游戏画面识别
→ 现有 GameState
→ 现有 analyzeGame / calculateBestDiscard
→ 可解释的悬浮 Copilot 展示
```
