## 剩余任务（连续实施，相关项一起完成）

1. **计番正确性**：检查仍仅按牌面而未验证面子的番种、不计/另计冲突、特殊型/组合龙附加番和复合拆分；补齐高价值与常见的缺失国标番种。优先消除虚报番数与错误“已达8番”，再减少漏报；无法准确认定仍标为“参考/待核”。不以“81番全覆盖”为完成门槛。
2. **真实和牌上下文**：按现有录牌布局酌情增加和牌张、门风/圈风、明暗/补杠、末张事件等小型输入并正确保存；对应番种以已记录事实为准。九莲宝灯须确认和牌前13张，不从14张最终形状臆断。无番和、组合龙及杠类复杂排斥规则未核实前不自动计。
3. **建议层与展示**：检查无效缺牌、重复使用实体牌、误导性末张提示；去除闲置的伪概率计算、重复推荐与不实际使用的包装层。建议是启发式，不能冒充精确胜率或结算。
4. **离线与 Android 交付**：移除运行时 Tailwind CDN 依赖，尽量本地打包必要样式/资源；检查离线启动、390×844 交互、键盘遮挡与 Android 真机/模拟器行为。只生成 Debug APK，不要求签名发行；做不到的环境实测如实列明。
5. **工程清理**：核对 README 功能表述与贡献信息；更新 GitHub Actions 已弃用的 Actions 版本，保留现有单套 CI，避免重复构建/重复验证与历史计划。不要引入新架构或视觉重设计。

## 验收方式（只做一次）

- 保留少量高风险规则正反例、输入完整性与四川不回退测试；**不再增加旧错误快照或按每个番种堆测试**。修复一个问题只改对应关键断言，能合并就合并。
- 完工时统一执行 `npm test && npm run typecheck && npm run build`，推送后核对一次 Actions Web/Android Debug APK。离线/真机验收需要实际设备或可用模拟器，不用 CI 通过冒充实测。
- 输出简短的“完成内容、剩余限制、验证结果”并精简本文件。当前无需另建 P4 阶段、总规划或反复请求批准。
